# 座位方位 P0 实施说明

日期：2026-11-04。关联需求：[原始设计](seat-view-system-design.md)。

设计可行：场馆与演出两层、演出级分区、事实与几何计算分离、显式标注示意，是本次实现的基础。需要修正的前提是：OSM 建筑轮廓不保证完整，也不能代表馆内分区；容量不能唯一反推出排数和坡度；社媒 API、票务图可获取性及许可均需逐项核实。参考项目的技术栈不等于本项目已安装相同依赖，本次没有添加 Three.js。

## 当前交付

- `/seat`：场馆和场次选择、SVG 分区高亮、票档图例、分区列表、前后/横向滑块、位置分享；键盘可选区，窄屏堆叠布局。登录后恢复分享链接。
- `/admin/seat-views`：管理员加载已有 JSON 或粘贴新场次，保存草稿通过校验后预览，确认核对后发布，亦可下架。普通用户只能读取已发布快照，管理接口再次检查管理员角色。
- 数据分两表 `t_seat_view_venue` / `t_seat_view_show`；分区数组暂存在演出 JSONB 内，整场原子更新。演出编号不可跨馆重新绑定。新场次应使用新编号。
- 五馆冷启动来自 `cuihairu/venue-seats` 的 MIT 示例，保留有效编号和演示票档，含标点/控制字符的编号改为稳定十六进制后缀及示意名称。上游也明确说明不是官方座位图。弧形分区取内外弧端点转为凸四边形，图坐标不是米。
- `/starline/seat-view/catalog` 提供已发布场馆、别名和演出映射。深链支持稳定场馆/演出编号；仅给场馆时也支持名称和精确别名。未匹配、场馆与演出不一致、未知分区均明确提示。

P0 复用现有应用与数据库连接，以独立业务包和路由实现；新增独立进程、PostGIS、Redis 缓存及消息队列在当前数据量没有必要。几何仅支持严格凸四边形，复杂分区需拆分为独立稳定编号；`frontEdge` 明确指定朝舞台的边，双线性插值保证位置留在区内。比例不是排座精度，不输出米制距离、遮挡或视力判断。

## 数据准备与部署

首次安装或升级按顺序执行：

1. `resources/database/upgrades/v1.1.0/261104_seat_view.sql`
2. `resources/database/upgrades/v1.1.0/261104_seat_view_demo.sql`

种子只插入不存在的编号，重复执行不会覆盖管理员校对结果。演示 JSON 位于 `resources/seat-view/demo-catalog.json`，用 `node resources/seat-view/generate-seed.mjs` 重建 SQL。MIT 许可证随源码和前端静态文件提供。

前端请求沿用登录态及现有 API baseURL。管理员接口为 `GET/PUT /starline/seat-view/admin/catalog`，PUT 正文为一份 `{venue, show}`，可从示例 JSON 数组取一项作为模板。每个分区包括 `code,label,level,priceTier,ring,frontEdge`；`ring` 为四个二维点，`frontEdge` 为 0 到 3 的边编号，`level` 为 1 内场、2 下层、3 上层。票档未知用 null。时间未知用 null，有时间时须使用带时区的 ISO 格式。

`show.status`：DRAFT / PUBLISHED / ARCHIVED；`show.provenance`：DEMO / REVIEWED_SCHEMATIC。真实场次经人工核对后使用后者，页面仍声明为示意。来源须为 HTTP/HTTPS 链接，不在服务端抓取该链接；`sourceNote` 填来源和核对依据。舞台几何使用与分区相同的示意坐标，x/y 为矩形中心，width/height 为范围，rotation 为角度。P0 矩形仅表达舞台范围；stageLayout 表达 END/CENTER/T 布局类别，不承诺还原 T 台形状。

不要以改变 provenance 的方式把上游 demo 变成真实场次。应取得具体演出的官方票务图，重新核对并录入分区、票价及舞台，再发布新演出编号。场馆名称/别名会影响该馆所有演出，修改时应同时复核。

## 票务图识别草稿模板

> 仅提取图片中能明确看见的分区编号、票档文字和舞台标注；看不清则标 null。输出每项原文和图片中的边界候选。所有坐标都使用图片坐标，禁止推测真实米制坐标、排距、容量、距离或遮挡。不要补全缺失分区。结果仅为待人工校对的草稿，不得自动发布。

识别后人工拆成凸四边形、统一稳定编号、标注前沿和来源，再通过后台草稿校验。

## 验证与当前边界

`node frontend/tests/seat-view.check.mjs` 检查五馆全部分区的插值边界、深链和非法参数。`SeatViewValidationTest` 检查凹陷/交叉/退化/非有限坐标、来源链接、时间、重复编号及全部种子。

尚未完成五馆 OSM 外轮廓采集和真实演出票务图人工核验，因此这是 P0 功能与演示数据交付，不是五馆真实场次数据验收。现有演出查询卡片结构没有场馆字段，尚未自动推断演出到场馆；用户通过座位方位入口选择场馆与演出。P1 的 3D、手机取景与遮挡，P2 的实拍和逐排逐座均未实现。
