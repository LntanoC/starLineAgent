# 长期记忆短测评

[返回回归总览](../README.md)

用买手机的常见场景验证跨会话记忆：喜欢小屏 → 临时帮朋友选购 → 改成喜欢大屏 → 删除偏好。固定 7 轮、5 个会话，复用已启动的服务。代码、产物和判定都独立于摘要测评。

## 剧本与验收

完整提问由 `LongTermMemoryMain.java` 的 `QUESTIONS` 保存，`--plan` 可以直接查看。为了控制调用量，新增、修改和删除轮次会明确请求整理记忆，并暂缓商品推荐；这些是测试用的提问，目的是观察记忆链路。

| 轮次 | 会话 | 用户场景 | 预期与证据 |
|---|---|---|---|
| 1 | A，新建 | 我一直喜欢小屏手机，单手方便，请记住 | 覆盖本轮的抽取成功；生效记忆新增小屏偏好 |
| 2 | B，新建 | 我对手机屏幕大小有什么偏好 | 问题不携带答案；人工核对回答是否明确说小屏 |
| 3 | B，续聊 | 临时帮朋友挑手机，朋友这次预算三千元，请整理记忆 | 覆盖本轮的台账为 NOOP；记忆快照没有变化，不能记成用户预算三千元 |
| 4 | C，新建 | 现在更喜欢大屏，之前的小屏偏好变了 | 新大屏偏好生效；旧条目失效且 `superseded_by` 指向新条目 |
| 5 | D，新建 | 我对手机屏幕大小有什么偏好 | 人工核对回答是否采用大屏偏好，不把小屏继续当现状 |
| 6 | D，续聊 | 删除屏幕大小偏好，保留其他记忆 | 大屏条目失效且无取代者；原有其他生效记忆保留 |
| 7 | E，新建 | 还记得我的屏幕偏好吗，没有就说不知道 | 记忆表没有该偏好；人工核对回答承认未知 |

第 3 轮同时涉及“临时任务”与“别人的信息”，只验证这句话不该变成用户画像，不拆成两项独立的质量结论。本组不衡量准确率，不代表所有说法都能处理正确。

上述七轮不专门验证后台门槛边界、全部清空、容量合并和淘汰；报告将这些独立验证标为 `UNCOVERED`。失败积压可能触发后台抽取，需要按台账记录实际来源。新会话召回是本套件的关键，不能用同一会话里的复述代替。

另有独立的自然聊天短剧本：同一会话自然提到小屏偏好，再问屏幕英寸、厚度与重量怎样影响握持，最后新开会话询问偏好。四条提问均不要求记住或整理，也不禁止工具调用。用 `--natural-plan` 查看，`--run-natural` 执行。

自然聊天测试从零积压开始。若仅剩先前七轮的最后一条未知询问，采集器先单独发送一次整理请求，核实 NOOP、记忆未变、待处理归零，再开始四轮；其他积压会停止并留待人工核对。准备请求不计入自然聊天证据。每轮保留待处理数、工具事件、抽取覆盖范围和至少三秒的观察记录；若有在飞抽取或积压达到三条，最多观察三十秒。门槛计数是未处理用户消息数：若主 Agent 提前整理，不能把第三轮对话冒充达到三条门槛。是否真正发生后台写入，以 `trigger_type`、条目 `source_type` 和正文共同判断；四轮后人工读取新会话答案，并通过指定撤回清理测试条目。

## 运行

需要 Java 17，本机 Maven 仓库或构建产物中的 PostgreSQL JDBC 驱动。HTTP、登录和数据库配置复用 `resources/initializer/common`。默认从 `bootstrap/src/main/resources/application.yaml` 读服务地址和数据库连接，不启动服务、不改模型或提示词、不直接改记忆表。

在仓库根目录执行，先看剧本和本地检查：

```bash
bash resources/regression/agent-long-term-memory/run.sh --plan
bash resources/regression/agent-long-term-memory/run.sh --self-test
```

账号默认 `admin`，密码通过环境变量提供。以下命令只检查基线，不发聊天请求：

```bash
RAGENT_MEMORY_PASSWORD=admin bash resources/regression/agent-long-term-memory/run.sh --inspect
```

服务可用时运行 7 轮：

```bash
RAGENT_MEMORY_PASSWORD=admin bash resources/regression/agent-long-term-memory/run.sh --run
```

运行独立的四轮自然聊天测评：

```bash
bash resources/regression/agent-long-term-memory/run.sh --natural-plan
RAGENT_MEMORY_PASSWORD=admin bash resources/regression/agent-long-term-memory/run.sh --run-natural
```

每次创建独立 `artifacts/<时间>-<随机值>/`。先保存原有记忆、待抽取消息、提示词和源码指纹；若已存在手机屏幕偏好、积压超过 5 条、存在在飞抽取或存量接近容量下限，停止执行。存量过滤较宽，碰到有关手机屏幕的其他记忆也可能停止，需人工看基线。

第 6 轮撤回本次测试偏好。**如果运行中断，尚未撤回的测试条目可能仍然生效**；先看最后一份快照，再通过聊天指定删除该条测试偏好。程序不自动清空账号、不直接写 SQL 回滚，也不自动重跑失败请求。

已知旧握笔测试可以用 `--cleanup-legacy` 指定撤回。其他测试残留使用 `--cleanup-memory ID '完整正文'`；程序先核对当前账号下该 ID 与正文完全一致，再通过聊天请求撤回，保存 `cleanup.json`、`cleanup.sse` 和 `cleanup-after.json`。若条目已失效，不重复发请求。清理不计入七轮结果。

采集器会继续记录有完整终止事件的 `INTERRUPTED` 回复，并把“回复完整成功”判为失败，同时读库检查工具是否已经产生变更。网络超时、缺少终止事件或消息 ID 等采集错误仍停止运行。继续采集不代表忽略失败，也不会自动重发该轮。

## 读报告

运行产物和另行整理的复核报告统一保存在 `artifacts/` 下

- `report.md`：逐轮结果和断言。
- `run.json`：剧本版本、配置来源、待抽取旧消息和源码指纹。配置中的模型名不冒充服务运行时的实际模型。
- `baseline.json`、`snapshot-*.json`：记忆、抽取台账和会话状态；数据库只读。
- `turn-*.sse`：原始响应，失败或中断也保留。
- `checks.json`：机器判定；`UNKNOWN`、`UNCOVERED` 都不能算通过。
- `prompts.json`：激活人设里显式配置的记忆提示词；未配置的槽位仍可能回退到内置提示词。

回答中的同义表达、否定和含糊措辞不能只凭关键词判定，所以第 2、5、7 轮留为人工核对；记录原文、结论和理由，另存 `manual-review.md`。数据库中含“小屏”也不证明整句语义正确，最终核对时还要读新增条目原文。

退出码 `0` 表示机器检查通过且无待核对项，`1` 表示失败，`2` 表示仍有人工核对项。完整短测评通常会返回 `2`，这不等于服务出错。
